# Mini Project 2 — Digital Content Attention Analyzer

This project studies how users behave while watching digital learning content (watch time,
pauses, replays, quiz scores, logins, etc.) and predicts whether they are likely to
**Complete** or **Not Complete** a piece of content.

## Folder Contents

| File | Purpose |
|---|---|
| `data_generator.py` | Creates the dataset `watch_history.csv` |
| `watch_history.csv` | The dataset used by the project (700 records) |
| `database_setup.sql` | SQL script that creates and fills the database tables |
| `sql_runner.py` | Runs the SQL script using SQLite and prints query results |
| `main.py` | The full project — cleaning, feature engineering, visualization, ML models, clustering, final prediction |
| `requirements.txt` | Python libraries needed |
| `*.png` | Graphs generated by the project |
| `content_analyzer.db` | SQLite database created after running `sql_runner.py` |

## What Was Actually Done In This Project

- Created a dataset with 700 rows covering 6 content types, 3 device types and 4 times of day,
  with behavior columns like watch time, pause count, replay count, notes taken, quiz score,
  login frequency and session duration.
- Built 5 SQL tables (`users`, `content`, `watch_history`, `quiz_results`, `login_activity`)
  and wrote SQL queries using `JOIN`, `GROUP BY`, `HAVING`, `CASE`, aggregate functions and
  a subquery.
- Wrote 6 Python classes: `User`, `Content`, `WatchHistory`, `QuizResult`,
  `EngagementAnalyzer`, `PredictionEngine`.
- Cleaned the data with Pandas and engineered new columns: `Watch_Percentage`,
  `Average_Session_Time`, `Replay_Ratio`, `Quiz_Performance`, and an `Engagement_Score`.
- Used NumPy to calculate mean, max, min, standard deviation of watch percentage and to
  normalize that column.
- Created 5 graphs with Matplotlib and Seaborn: content completion trend, watch-time
  distribution, quiz-score distribution, daily login pattern, and a correlation heatmap
  (watch time, replay count, quiz score, login frequency, session duration vs completion).
- Trained and compared 4 ML models (KNN, Naive Bayes, Decision Tree, Random Forest) on
  `Completion_Status`, measuring Accuracy, Precision and Recall for each, and picked the
  best model automatically.
- Applied K-Means clustering on behavior-only features (watch %, replay count, quiz score,
  login frequency, session duration) — deliberately **without** using `Completion_Status`
  — and grouped users into Passive Users, Regular Learners and Highly Engaged Learners.
- Built a final sample prediction matching the exact example from the project brief
  (Python Tutorial, 40 min duration, 36 min watched).

## Code Explanation

### `data_generator.py`
Builds 700 synthetic watch-history rows. For each row it randomly decides which "engagement
group" a user falls into (high engagement, medium engagement, or low engagement) and generates
watch time, pauses, replays, notes, quiz score, login frequency and session duration to match
that group. It then calculates the watch percentage and applies simple rules (high watch % and
high quiz score → Completed) with a bit of randomness mixed in so the resulting patterns feel
close to real behavior instead of a perfectly clean rule.

### `database_setup.sql`
Creates the five tables described in the project brief, inserts sample rows, and includes SQL
queries covering the exact requirements listed: most watched content, average watch time,
highest engagement content, users with low completion, average quiz score, content with the
highest replay count (using `HAVING`), a `CASE` statement to label users, and a subquery for
users with above-average login frequency.

### `sql_runner.py`
Connects to a SQLite file (`content_analyzer.db`), executes the whole SQL script, then runs
several of the queries individually with `cur.execute()` so their results print directly in
the terminal.

### `main.py`
The main application.

- **Classes**
  - `User` — id, device, login frequency.
  - `Content` — content type and duration.
  - `WatchHistory` — watch time, pauses, replays, duration, with a `watch_percentage()` method.
  - `QuizResult` — quiz score and number of attempts.
  - `EngagementAnalyzer` — takes the cleaned DataFrame and can report the most engaging content
    types and the completion rate broken down by device.
  - `PredictionEngine` — encodes categorical columns, trains all 4 ML models, tracks accuracy/
    precision/recall for each, and keeps the best model ready for predictions.

- **Functions**
  - `clean_and_engineer(df)` — removes duplicates/missing rows and builds the new feature
    columns (`Watch_Percentage`, `Average_Session_Time`, `Replay_Ratio`, `Quiz_Performance`,
    `Engagement_Score`).
  - `numpy_stats(df)` — NumPy statistics on watch percentage, plus a normalized column.
  - `make_visualizations(df)` — builds and saves all 5 required graphs.
  - `run_kmeans(df)` — clusters users purely on behavior columns and names each cluster.
  - `main()` — runs every step in order, prints the model comparison table, and finally predicts
    completion for the "Python Tutorial, 36 out of 40 minutes watched" example from the brief.

## How To Run This Project

1. Make sure Python 3.8+ is installed.
2. Open a terminal inside the `project2_content_analyzer` folder.
3. Install the required libraries:
   ```
   pip install -r requirements.txt
   ```
4. (Optional — the CSV is already included) Regenerate the dataset:
   ```
   python data_generator.py
   ```
5. Run the SQL part to see the database in action:
   ```
   python sql_runner.py
   ```
6. Run the full project (cleaning, visualization, ML, clustering, final prediction):
   ```
   python main.py
   ```
7. Check the folder for the generated `.png` graph files and the `content_analyzer.db` database file.

The final part of the terminal output will show something like:
```
Content: Python Tutorial
Duration: 40 minutes | Watched: 36 minutes
Predicted Completion: Completed
Engagement Level: HIGH
```
